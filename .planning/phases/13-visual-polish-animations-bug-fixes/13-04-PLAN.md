**Part A: Refine page transitions in app.vue**

Review the existing page transition in `app.vue`. The current transition uses `opacity + translateY`. Refine it for smoothness:

1. Ensure `<NuxtPage>` is wrapped with a `<Transition>` (or uses Nuxt's built-in `pageTransition` config).
2. Set transition mode to `out-in` to prevent overlap glitches.
3. Use these CSS transition properties for the `page-*` classes:
   - `page-enter-active, page-leave-active`: `transition: all 0.3s ease`
   - `page-enter-from`: `opacity: 0; transform: translateY(10px)`
   - `page-leave-to`: `opacity: 0; transform: translateY(-10px)`
4. Only animate `opacity` and `transform` (compositor-friendly, no layout jank).
5. Keep it subtle — 0.3s duration, small translateY offset. Not dramatic.

**Part B: Add staggered v-motion animations to lists/buttons**

The `@vueuse/motion` module is already installed. Apply staggered entrance animations to:

1. **index.vue menu buttons** — Wrap each GameButton in a v-motion directive:

   ```vue
   <GameButton
     v-motion
     :initial="{ opacity: 0, y: 30 }"
     :enter="{ opacity: 1, y: 0, transition: { delay: index * 100 } }"
   />
   ```

   Since buttons are not in a v-for, manually assign delays: 0ms, 100ms, 200ms, 300ms for the 4 buttons.

2. **players.vue player inputs** — If player name inputs are in a v-for loop, add v-motion with index-based stagger:

   ```vue
   <div
     v-for="(player, index) in players"
     v-motion
     :initial="{ opacity: 0, x: -20 }"
     :enter="{ opacity: 1, x: 0, transition: { delay: index * 80 } }"
   />
   ```

3. **leaderboard.vue items** — If leaderboard items are rendered via GameScrollList, check if stagger can be applied at the item level. If GameScrollList renders items internally, consider adding a `stagger` prop or applying v-motion to the items inside GameScrollList. If not feasible without refactoring GameScrollList, apply v-motion to the GameScrollList wrapper element instead (single fade-in).

**Part C: Ensure prefers-reduced-motion is respected**

The global CSS rule from plan 13-01 handles CSS animations. For v-motion directives, check if `@vueuse/motion` respects `prefers-reduced-motion` automatically. If not, add a check:

```ts
const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches
```

And conditionally set `:initial` and `:enter` to empty objects when reduced motion is preferred. This can be done via a simple composable or inline check.

Keep animations SUBTLE. The goal is polish, not distraction. Durations should be 200-400ms. Delays should stagger by 60-100ms per item.
