  <action>
Create `apps/game/tests/e2e/helpers/game-flow.ts` with the following shared helpers extracted from duplicated local functions across spec files:

**Helper functions to create:**

1. **`hideDevtools(page: Page)`** -- Add CSS to hide Nuxt devtools overlay. Extracted from scoring-flow.spec.ts, game-complete-flow.spec.ts, full-game-workflow.spec.ts (all 3 are identical).

2. **`submitPlayerAnswers(page: Page, count: number, answers?: string[])`** -- Submit answers for `count` players. CRITICAL: Must be feature-flag-aware. Check if `[data-testid="game-answer-input"]` is visible before attempting to fill. If not visible (feature flag off), just click the submit button. If visible and answer provided, fill then click. Wait for each turn transition. After all players, wait for `[data-testid="game-all-submitted"]` to appear.

3. **`navigateToResults(page: Page)`** -- Click the NEXT button on game page, wait for `/results/` URL, use `__zustand__` to load game state from DB, wait for player entries to render. Consolidated from the 3 nearly-identical implementations in scoring-flow.spec.ts, game-complete-flow.spec.ts, and full-game-workflow.spec.ts.

4. **`assignScores(page: Page, scores: number[])`** -- For each player index, find `[data-testid="results-player-entry-{i}"]`, click its increment button `scores[i]` times. Small delay (80-100ms) between clicks to prevent UI race conditions.

5. **`confirmScoresAndWaitForModal(page: Page)`** -- Click `[data-testid="confirm-scores"]`, wait for leaderboard overlay auto-dismiss + decision modal appearance. Wait for either `[data-testid="next-round"]` or `[data-testid="leaderboard-button"]` to appear (up to 15s timeout).

6. **`goToNextRound(page: Page)`** -- Click `[data-testid="next-round"]`, wait for `/game/` URL (goes through round-start which may be too fast to observe).

7. **`finishGame(page: Page)`** -- Click `[data-testid="leaderboard-button"]`, wait for `/leaderboard/` URL.

8. **`setupMultiplayerGame(page: Page, playerNames: string[])`** -- Navigate to `/players`, increase player count to match `playerNames.length`, fill name inputs, click start, wait for `/game/` URL. Uses `data-testid` selectors throughout.

9. **`startGameWithDefaults(page: Page)`** -- Navigate to `/players`, click start with default 2 players, wait for `/game/` URL.

10. **`startGameAndGoToResults(page: Page, playerCount?: number)`** -- Convenience: startGame, submitPlayerAnswers (empty), navigateToResults. Used by scoring-flow and similar specs. Default playerCount = 2.

All helpers should:

- Use `data-testid` selectors exclusively (no CSS class selectors)
- Use Playwright's built-in auto-waiting where possible
- Prefer `await expect(locator).toBeVisible({ timeout })` over `waitForTimeout`
- Include JSDoc comments explaining purpose and parameters
