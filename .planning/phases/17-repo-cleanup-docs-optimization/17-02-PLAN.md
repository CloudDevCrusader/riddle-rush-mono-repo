<task type="auto">
  <name>Task 1: Install Knip and create monorepo configuration</name>
  <files>knip.json, package.json</files>
  <action>
1. Install Knip: `pnpm add -wD knip`

2. Create `knip.json` at repo root with this configuration:

```json
{
  "$schema": "https://unpkg.com/knip@5/schema.json",
  "workspaces": {
    ".": {
      "entry": ["main.py"],
      "ignoreDependencies": [
        "@anthropic-ai/claude-agent-sdk",
        "@composio/claude-agent-sdk",
        "@composio/core",
        "@e2b/code-interpreter",
        "@langchain/openai",
        "@voltagent/core",
        "@voltagent/mcp-server",
        "ai",
        "langchain",
        "@trigger.dev/sdk",
        "@composio/openai",
        "@pnpm/filter-workspace-packages"
      ]
    },
    "apps/game": {
      "entry": ["app.vue", "nuxt.config.ts"],
      "project": ["**/*.{ts,vue}"],
      "ignore": ["**/*.spec.ts", "**/*.test.ts", "tests/**"]
    },
    "packages/*": {}
  }
}
```

3. Run `npx knip --reporter compact` to generate baseline report. Capture output.

4. Review the report for false positives — Nuxt auto-imported composables and components WILL appear as unused. DO NOT remove those. Instead, add them to the `ignore` list in knip.json if needed.

5. Add a `knip` script to root package.json: `"knip": "knip --reporter compact"`

6. Run `pnpm run workspace:check` to verify nothing broke.
   </action>

   </verify>
   <done>Knip installed, configured for monorepo with Nuxt-aware ignore patterns, baseline report generated. False positives identified and suppressed. knip script added to root package.json.</done>
   </task>

<task type="auto">
  <name>Task 3: Run dependency audit and fix critical vulnerabilities</name>
  <files>package.json, pnpm-lock.yaml</files>
  <action>
1. Run `pnpm audit` to get the full vulnerability report. Capture the output and identify:
   - The 1 critical vulnerability (package name, advisory, affected version)
   - The 10 high severity vulnerabilities

2. Address the critical vulnerability first:
   - Check if the vulnerable package has a patched version: `pnpm outdated -r <package-name>`
   - If a safe update exists: `pnpm update -r <package-name>`
   - If the package is a transitive dependency, check if the direct parent has an update
   - If no fix available, document in the SUMMARY as a known issue with mitigation

3. Apply safe updates for high-severity vulnerabilities:
   - Run `pnpm outdated -r` to see all outdated packages
   - For each high-severity vuln, check if updating to the latest minor/patch resolves it
   - Apply updates one category at a time (e.g., all vite-related, all nuxt-related)
   - Run `pnpm run workspace:check` after each batch of updates

4. For moderate/low severity vulnerabilities:
   - If they can be fixed with a simple `pnpm update -r`, do it
   - If they require major version bumps, document as deferred in the SUMMARY

5. Run final verification:
   - `pnpm run workspace:check`
   - `pnpm run build`
   - `pnpm audit --audit-level critical` (should report 0 critical)

6. Document the before/after vulnerability counts in the SUMMARY.
