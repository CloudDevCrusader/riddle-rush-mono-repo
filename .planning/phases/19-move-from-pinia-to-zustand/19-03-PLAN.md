Test cases:

- **Old Pinia format detected**: Set localStorage `game-settings` to flat JSON `{"maxPlayersPerGame":4,"soundVolume":50}`. Call migrateFromPinia(). Assert localStorage now contains `{"state":{"maxPlayersPerGame":4,"soundVolume":50},"version":0}`.

- **SSR guard**: When window is undefined, migrateFromPinia() returns without error.

Mock localStorage with vi.stubGlobal or a mock storage object.

**2. Clean up E2E test helpers** that reference `window.__pinia__`:

These E2E helpers use `(window as any).__pinia__` to access store state for diagnostics and wait conditions. After Pinia removal, `__pinia__` won't exist at runtime.

**Strategy**: Since E2E tests run against the actual browser app, and the Zustand stores are not exposed on `window` by default, the E2E helpers that relied on Pinia internals need updating. Two options:

Option A (preferred): In the Zustand plugin (`plugins/zustand.ts`), expose stores on `window` in development mode for E2E test access:

```typescript
if (process.dev) {
  window.__zustand__ = { game: gameStore, settings: settingsStore }
}
```

Then update E2E helpers to use `window.__zustand__` instead of `window.__pinia__`.

Option B: Remove store-based E2E wait conditions and rely on DOM-based waits only.

Go with Option A -- it's minimal change and preserves E2E test capabilities.

For each E2E file, search-and-replace:

- `(window as any).__pinia__` -> `(window as any).__zustand__`
- `pinia._s?.get('game')` -> `window.__zustand__?.game?.getState()`
- `pinia.state?.value?.game` -> `window.__zustand__?.game?.getState()`
- `pinia._s?.get('settings')` -> `window.__zustand__?.settings?.getState()`
- Remove references to `pinia._s?.get('round')` or `pinia._s?.get('socket')` (these stores don't exist in Zustand)

Update the following E2E files:

- `tests/e2e/helpers/waits.ts` (heaviest Pinia usage -- many wait conditions)
- `tests/e2e/helpers/diagnostics.ts`
- `tests/e2e/full-game-workflow.spec.ts`
- `tests/e2e/game-complete-flow.spec.ts`
- `tests/e2e/scoring-flow.spec.ts`

Also update `plugins/zustand.ts` to expose stores on window in dev mode.
